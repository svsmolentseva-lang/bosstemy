# Босс темы - каркас бота

Класс готовится к контрольной вместе: у темы есть полоса здоровья, и каждый
верный ответ снимает урон. Проект для хакатона «Идея Фикс», направление
«Арена развлечений», номинация «Продвинутая разработка».

## Быстрый старт без MAX

Токен, интернет и установка библиотек не нужны: консольный режим, тесты и
мини-приложение работают на голом Python 3.10+. httpx требуется только для
связи с MAX.

```bash
python run_console.py
```

Дальше по шагам:

```
Учитель > /класс 7 «Б»
          ← бот выдаёт код, например RE-BV9
Учитель > /рейд Дроби
Учитель > !кто Аня          ← переключиться на другого человека
Аня     > /вход RE-BV9 Аня
Аня     > /бить
Аня     > 5/6               ← ответ на вопрос
Аня     > /вопрос Сколько будет 1/2 + 1/4? | 3/4 | 3/4 | 2/6 | 1/8
Аня     > !кто Учитель
Учитель > /проверка
Учитель > /панель
```

### Если база не открывается

`disk I/O error` при старте означает, что папка не поддерживает файловые
блокировки SQLite - так бывает в iCloud, Dropbox и на сетевых дисках.
Положите базу в обычную папку:

```bash
DB_PATH=~/boss.db python3 run_console.py
DB_PATH=~/boss.db python3 run_web.py
```

Бот и мини-приложение должны смотреть в **одну и ту же** базу.

## Тесты

```bash
python -m pytest -q
```

Если pytest не установлен:

```bash
python tests/run_without_pytest.py
```

Тесты проверяют то, о чём спросит жюри: урон засчитывается только за верный
ответ, повторный ответ ничего не даёт, слишком быстрый ответ не считается,
один ученик не может вынести босса в одиночку, класс добивает вместе, отчёт
показывает провальные вопросы и тех, кто не заходил.

## Запуск в MAX

Бота больше не заводят через переписку с сервисным ботом. Порядок такой:

1. **Профиль на платформе.** Подключиться к dev.max.ru и создать
   верифицированный профиль организации, ИП или самозанятого. Физическое лицо
   бота завести не может. Школа - юридическое лицо, поэтому верификацию
   проходит она.
2. **Создать бота** в разделе «Чат-боты»: логотип, имя, описание.
   Ник назначается по шаблону вида `idИНН_bot`.
3. **Модерация** - до 48 рабочих часов. Пока идёт проверка, настройки менять
   нельзя, и пользоваться ботом тоже нельзя: он появляется в поиске MAX только
   после статуса «создан».
4. **Получить токен** и вписать его в `.env`.
5. **Поднять сервер** с доменом и https, указать адрес мини-приложения в
   настройках бота, зарегистрировать вебхук.

```bash
docker build -t boss-temy .
docker run --env-file .env -p 8080:8080 boss-temy
```

Мини-приложение MAX принимает **только https** и валидный домен: localhost
годится лишь для разработки. Само по себе мини-приложение не живёт - оно
всегда открывается из чат-бота.

Боевой режим - вебхук (`run_all.py`): long polling платформа разрешает только
на отладке. Бот и арена поднимаются одним процессом на одном порту:
арена на `/`, события от MAX на секретный путь из `WEBHOOK_PATH`.

**Не проверено:** точные адреса методов и структуру событий нужно
сверить с документацией на dev.max.ru. Вся сеть собрана в `app/transport.py` -
если что-то отличается, правится только этот файл, остальной код не трогается.
Открытый вопрос к организаторам: как школьная команда получает доступ к
платформе разработчика.

## Как устроен код

```
app/config.py      настройки и правила игры (урон, лимиты) - меняются без правки кода
app/db.py          SQLite: схема и три функции для запросов
app/logic.py       правила игры. Ничего не знает про мессенджер - поэтому тестируется
app/texts.py       все реплики бота в одном месте
app/transport.py   единственный файл, который ходит в сеть
app/handlers.py    команда → действие → ответ
app/seed.py        стартовый банк вопросов
app/webapp.py      HTTP-сервер мини-приложения (только стандартная библиотека)
app/auth.py        кто открыл экран; проверка подписи MAX Bridge - заглушка
web/index.html     сам экран с боссом
web/raids.html     список открытых рейдов класса - первый экран ученика
web/teacher.html   панель учителя
web/admin.html     кабинет администратора
```

Главная идея разделения: `logic.py` можно проверять и показывать без токена,
интернета и мессенджера. Когда доступ к MAX появится, подключается
`MaxTransport` - и та же логика начинает работать в чате.

## Правила игры и защита от накрутки

| Правило | Зачем |
|---|---|
| Урон 20 за верный ответ | шкала движется заметно, но босс не падает от одного человека |
| Неверный ответ - 0 урона, без штрафа | ошибаться безопасно, иначе слабые перестают заходить |
| Ответ быстрее 3 секунд не считается | это тык наугад, а не решение |
| Повторный верный ответ на тот же вопрос - 0 | нельзя фармить один лёгкий вопрос |
| Не больше 12 ударов в день на человека | один отличник не выносит босса за класс |
| Очки автору - за чужие ошибки на его вопросе | награда за трудный вопрос, а не за факт отправки |
| Если на вопросе ошибаются больше 80% - очков нет | вопрос сломан, а не хитёр |

Все числа лежат в `app/config.py` и меняются переменными окружения.

## Кабинет администратора

```bash
python3 run_web.py
# открыть http://localhost:8080/admin?t=КЛЮЧ
```

Ключ печатается при первом запуске и лежит в файле `.admin-token` рядом с ботом
(его же показывают «панель.command» и «туннель.command»). В кабинете заводят
классы и учителей и выдают две ссылки: код класса для учеников и личную ссылку
учителя на панель.

Модель данных рассчитана на живую школу:

| Так бывает | Как устроено |
|---|---|
| Один учитель ведёт несколько классов | связка учитель-класс-предмет лежит в таблице `teaching`, а не полем у пользователя |
| Один учитель ведёт в классе несколько предметов | в `teaching` по строке на предмет, в панели переключатель |
| В классе идёт несколько рейдов сразу | у рейда есть предмет; открытых рейдов в классе может быть много |

Босса на рейд выбирает учитель. Ученик, зайдя в «Босса темы», видит все
открытые рейды своего класса по разным предметам и сам решает, к какой теме
готовится сегодня.

## Что хранится о детях

Только имя (без фамилии) и код класса. Ни школы, ни контактов, ни возраста.
Ученик входит по коду, который учитель диктует вслух, и называет себя логином -
фамилии в игре не нужны.

Учитель видит, кто заходил и насколько активно, какие темы просели и сколько
вопросов в банке. Кто именно как ответил - не видит никто: иначе дети начнут
бояться ошибиться при учителе.

## Мини-приложение (экран с боссом)

```bash
python3 run_web.py
# открыть http://localhost:8080/join - вход по коду класса
```

Босс, шкала здоровья, строй класса и вопрос. Верный ответ двигает шкалу у всех
сразу, у босса отваливаются щиты и меняется лицо. На нуле - «Босс повержен».

Время ответа меряется **на сервере**, а не в браузере: клиенту в таких вещах
верить нельзя. Проверено - автокликер получает «слишком быстро, урон не
засчитан».

## Чего ещё нет

Проверка подписи MAX Bridge (пока режим разработки), уведомления классу при
объявлении рейда, вебхук вместо long polling, перенос на Postgres. Это работа на три недели, 20 октября - 8 ноября.


## Порядок развёртывания

1. **Сегодня, на своём компьютере.** `python run_console.py` и
   `ALLOW_DEV_AUTH=1 python run_web.py` - ничего больше не нужно.
2. **Пилот в классе без MAX.** Запустите `пилот.command` - он поднимет сервер и
   выдаст ссылку вида `http://192.168.х.х:8080/join?code=КОД`. Она работает для
   всех, кто в той же сети Wi-Fi: в классе этого достаточно, и не нужны ни
   туннели, ни домены. Ученик открывает ссылку, называет имя и получает личную
   ссылку с секретом - подставить чужое имя в адресе нельзя.

   Если класс сидит по разным сетям, нужен туннель наружу
   (`cloudflared tunnel --url http://localhost:8080`). Учтите: домены
   `trycloudflare.com` у российских провайдеров часто не резолвятся -
   тогда остаётся только локальная сеть или настоящий хостинг.

   Команда `/ссылки` в боте показывает учителю общую ссылку и личные ссылки тех,
   кто вошёл.
3. **Настоящий MAX.** Школа проходит верификацию → токен у MasterBot →
   сервер с доменом и сертификатом → `WEBAPP_URL=https://…` → `run_all.py`.
